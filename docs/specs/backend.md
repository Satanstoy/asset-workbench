# 素材制作工作台后端规格

2026-11-10 · v1.0

领域用语以 [CONTEXT.md](../../CONTEXT.md) 为准。后端规格细化[项目总规格](../../outputs/素材制作工作台-开发规格.md)的接口、任务执行及测试约定。模拟参数、素材复用和失败恢复遵循已经确认的 Grill Me 决定。

## 问题陈述

用户需要在图片上传和制作任务受理后获得可靠的确认，之后随时查询自己任务的进度和结果。Java 必须在浏览器关闭、演示身份切换、制作步骤失败或数据库短暂断连时，仍能让任务记录准确反映已经发生的事。

## 解决方案

Java 提供演示身份、模板、素材和制作任务接口。MySQL 保存业务记录并承担制作任务队列，素材文件保存在持久卷。单个后台 worker 按序执行素材检查、模拟生成和结果整理。前端从只读接口取得已提交的任务状态和制作阶段。

## 用户故事与验收条件

1. **BE01 · 浏览模板要求。** 作为用户，我希望能读到每种模板的素材要求，以便准备图片。

   **验收**　至少有两个模板分类及单图、双图模板。分类筛选返回匹配模板。详情返回封面、描述、所需图片数量、格式、字节和像素限制。种子封面可通过 Java 访问。
2. **BE02 · 用独立身份制作。** 作为评审者，我希望在 A 和 B 之间切换，以验证素材和任务各自归属。

   **验收**　A 开始上传后切换为 B，已经通过身份校验的上传仍归 A。切换完成后，旧会话发起的受保护请求被拒绝。B 无法读取 A 的任务或引用 A 的素材，切回 A 后可以查看原有个人历史。
3. **BE03 · 上传可用的素材。** 作为用户，我希望 Java 只在文件确实可用时返回素材 ID，以便放心提交制作。

   **验收**　符合目标模板限制的 JPEG 或 PNG 返回素材 ID。超出 5 MiB、超过 2500 万像素、格式伪装或内容损坏时被拒绝。文件已保存而数据库写入失败时，响应不含素材 ID。明确回滚时清理文件，结果未知时保留文件。
4. **BE04 · 固定本次任务输入。** 作为用户，我希望可以复用素材，同时保证已经受理的任务不受后续选图影响。

   **验收**　同一演示身份的素材满足目标模板要求时可以跨模板复用。双图模板接受两个上传位引用同一素材，也接受两份不同素材，并按上传位顺序保存。错误数量、无效素材或跨身份引用会被拒绝，且不会留下部分任务记录。
5. **BE05 · 受理后继续提交。** 作为用户，我希望立即获得任务标识，以便继续使用网站。

   **验收**　请求在制作完成前返回已持久化的初始任务记录。第一项执行时，第二项可受理并等待。第一项结束后第二项开始。关闭页面或停止查询后，后台仍会推进任务。
6. **BE06 · 查看制作阶段和结果。** 作为用户，我希望知道任务执行到哪一步，以及最终是否成功。

   **验收**　三个制作阶段按序进入，可通过调长模拟耗时逐一观察。成功记录提供可打开的结果图。双图拼贴用上传素材合成，明信片使用预置图。指定阶段失败时保留该阶段和原因，跳过后续阶段，并继续处理队列。结果图生成、保存或读取预置图失败时，只将当前任务标记为制作失败。
7. **BE07 · 数据库恢复后继续制作。** 作为用户，我希望数据库短时故障不会让正在执行的阶段重复运行。

   **验收**　阶段已执行但状态写入超时时，worker 暂停领取新任务。数据库恢复后根据任务记录识别写入是否已生效，必要时补写，再用本次阶段结果继续。查询不可用时返回请求错误，记录中不会凭空出现制作失败。
8. **BE08 · 重启后核对个人历史。** 作为用户，我希望重启后看到明确的任务状态。

   **验收**　遗留的处理中任务保留原阶段并标为制作失败。等待任务在启动后继续排队。终态保留，重选原演示身份后可恢复个人历史。查询接口按身份过滤并稳定倒序返回记录。
9. **BE09 · 控制演示耗时与失败。** 作为评审者，我希望可指定哪项任务失败及失败位置，以便重复验证。

   **验收**　开启演示控制后，每项任务可独立配置阶段耗时与一个失败阶段。关闭演示控制时，带模拟覆盖参数的请求被拒绝。同批其他任务按自己的配置执行。

## 实现决策

### 接口契约

所有接口由 Java 实现，浏览器通过 Next.js 的同源路径访问。表中 ID 均为 JSON 字符串，客户端把它当作不透明标识。日期时间使用 ISO 8601。

| 请求 | 访问 | 成功响应 |
| --- | --- | --- |
| `GET /api/session` | 公开 | 200，`{ user: null }` 或 `{ user: { id, displayName } }`。 |
| `POST /api/session` | 公开 | 200，请求体 `{ userId }` 取 `demo-a` 或 `demo-b`，返回会话用户并更新 Cookie。 |
| `GET /api/templates` | 公开 | 200，`{ categories, templates }`。可传 `category`，筛选后分类列表仍完整，无匹配时模板列表为空。 |
| `GET /api/templates/{id}` | 公开 | 200，模板详情。 |
| `POST /api/assets` | 需会话 | 201，multipart 字段为 `templateId` 和 `file`，返回 `{ id, mimeType, sizeBytes }`。 |
| `POST /api/tasks` | 需会话 | 202，请求体为 `{ templateId, assetIds, simulation? }`，返回已提交的初始任务记录。 |
| `GET /api/tasks` | 需会话 | 200，`{ tasks }`。仅当前身份，按任务序号倒序，可组合 `templateId` 和 `activeOnly=true`。 |
| `GET /api/tasks/{id}` | 需会话 | 200，一项当前身份的制作任务。 |
| `GET /api/tasks/{id}/result` | 所属演示身份 | 200 返回任务生成的 PNG。无会话返回 401，任务归属不匹配、未成功或无生成文件返回 404。 |
| `GET /api/demo-images/{filename}` | 公开 | 200，返回项目自带的白名单图片。封面、预置结果图和演示样例均可经此访问。 |

- 模板响应包含 `id`、`title`、`category`、`coverUrl`、`description`、`requiredImageCount`、`acceptedMimeTypes`、`maxFileSizeBytes`、`maxImagePixels`。默认限制分别为 5,242,880 字节和 25,000,000 像素。
- 任务响应包含 `id`、`templateId`、`templateTitle`、`createdAt`、`status`、`stage`、`resultUrl`、`failure`。等待时 `stage` 为 `null`，只有成功时 `resultUrl` 有值，只有失败时 `failure` 有值。失败对象包含 `code` 和 `message`。
- 演示控制开启时接受可选 `simulation.stageDelayMs` 和 `simulation.failAtStage`。耗时按任务保存，单位为毫秒，整数范围 0–10000，默认每阶段 2000。失败阶段可取任一阶段枚举，省略时执行正常流程。
- 参数和素材校验错误用 400，缺少有效会话用 401，模板或任务不存在以及任务归属不匹配用 404，上传超限用 413，数据库暂时不可用用 503。错误响应为 `{ error: { code, message } }`。直接引用不可用的素材返回通用校验错误。受保护响应和会话响应禁止共享缓存。
- 制作失败原因有稳定码和可读文案，至少区分素材文件不可用、模拟失败、预置结果图不可用和重启中断。请求出错通过 HTTP 错误表达，与制作任务响应中的 `failure` 分开。

### 会话、上传与受理

- Java 通过 HttpOnly 会话 Cookie 解析演示身份。切换身份使旧会话失效并建立新会话。业务请求通过校验时捕获身份，后续访问和写入使用该身份。浏览器重新选择 A 或 B 可以找回对应业务记录。
- 上传校验根据目标模板执行。先检查实际字节数、实际图片格式和尺寸，以宽类型计算像素乘积，通过限制后检查图片内容可解码。素材记录保存归属、实际格式、字节数、尺寸和受控的本地存储位置。
- 文件写入成功后提交素材记录。两者确认完成才返回 201。明确回滚时尽力清理此次文件。提交结果未知时保留文件，避免删除可能已被记录引用的内容。应用管理的素材文件保存在持久卷。
- 任务受理校验模板、素材数量、每个位置的素材归属及模板要求，并在同一事务内保存任务和全部任务输入。输入按上传位编号保存，任务和位置的组合唯一，素材 ID 可在不同位置重复。每次成功受理生成独立任务，受理事务完成后才返回 202。
- 任务查询不触发领取或状态推进。个人历史包含当前演示身份所有已受理任务，首版不分页。

### 单 worker 与持久化

| 时点 | 任务状态 | 制作阶段 |
| --- | --- | --- |
| 受理完成 | `PENDING` | 空 |
| worker 领取 | `PROCESSING` | `CHECK_ASSETS` |
| 素材检查成功 | `PROCESSING` | `GENERATE` |
| 模拟生成成功 | `PROCESSING` | `FINALIZE` |
| 结果整理成功 | `SUCCEEDED` | `FINALIZE` |
| 任一阶段失败 | `FAILED` | 发生失败的阶段 |

- worker 从已提交的等待任务中按任务序号领取最早一项。领取和推进以原任务状态、原制作阶段作为写入条件。每步进入前先保存阶段，再在数据库事务之外执行步骤和模拟等待。首版只持久化当前阶段，无阶段历史接口。
- 素材检查确认输入文件仍可读。模拟生成使用已保存的耗时和失败参数。双图拼贴按输入顺序生成左右两幅图，等比缩放且保留全图。结果整理在素材卷原子发布 PNG，再写入成功状态及结果地址。明信片在结果整理检查预置结果图。失败时一并保存终态、阶段和原因，后续步骤停止。
- 状态写入暂时失败时保留当前执行结果，在间隔重试期间停止领取下一项。恢复后先读回当前任务。如果目标状态已提交，继续后续流程。如果仍是预期旧状态，补写同一次状态变更。如果已是终态，以数据库记录为准。阶段结果保存在当前进程，写入重试不会重跑已经完成的阶段。
- 启动时在领取队列前，将上个进程遗留的 `PROCESSING` 记录标为 `FAILED`，保留原阶段并写入 `PROCESS_INTERRUPTED` 和「服务重启，处理已中断」。随后按顺序领取等待任务。任何查询或启动操作都不能将终态变回处理中。

## 测试决策

从可观察的业务入口验证结果。阶段控制用于可重复地观察边界，持久化、归属和受理由 MySQL 或 HTTP 边界测试验证。

| 测试入口 | 最先验证的行为 |
| --- | --- |
| 制作工作流与任务查询 | 使用可控阶段观察三个状态边界。逐一注入阶段失败，确认后续阶段未执行、终态稳定且下一项任务可以执行。覆盖预置结果图缺失。 |
| 状态写入恢复 | 分别模拟写入未提交和写入已提交但未收到确认。恢复后都能推进，已完成阶段执行一次。故障期间下一项任务保持等待。 |
| MySQL 事务和启动处理 | 受理记录和输入一并提交。重复素材保留两个位置。查询只读，个人历史稳定倒序。重启时等待、处理中及终态任务按各自规则处理。 |
| HTTP 与文件存储 | 覆盖旧会话、切换时已通过校验的请求、跨身份读取和素材引用、有效图片、格式伪装、文件和像素边界，以及上传提交明确回滚和结果未知。 |
| 种子和容器验收 | 启动后从接口读取单图和双图模板，逐一请求种子封面与结果图。用 README 命令演示成功、指定阶段失败、调耗时和重启。 |

TDD 的首条测试在制作工作流入口验证三个制作阶段依次可见，随后增加指定阶段失败后停止的测试。第二批验证 MySQL 持久化、归属和暂时故障恢复。Java CI 运行测试和构建。

## 交付说明

README 提供库表和种子初始化、上传卷路径、会话切换、演示控制开关和调用命令、已知限制及数据重置方法。模板详情由前端读取 `maxImagePixels` 并展示像素限制。前端把 503 等查询错误处理为进度查询异常。以上两项纳入前端规格的输入。


### 历史删除与会话退出

`DELETE /api/tasks/{id}` 对所属身份的终态任务写入删除标记并返回 204。无会话返回 401，不可见任务返回 404，非终态返回 409。列表、单项和专属预览均不再公开已删除任务。素材和生成文件留在原存储中。

`DELETE /api/session` 使当前演示会话失效并返回 `{"user":null}`。
