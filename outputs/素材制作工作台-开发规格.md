# 素材制作工作台开发规格

2026-11-10 · v2.0 · Spec Writing

领域用语以 [CONTEXT.md](../CONTEXT.md) 为准。交付要求来自 小影科技全栈开发笔试 R-01 至 R-14，产品取舍来自已确认的 Grill Me 决定。后端接口和执行细节见[后端规格](../docs/specs/backend.md)，页面交互和异步状态见[前端规格](../docs/specs/frontend.md)。

## 问题陈述

用户想按模板提交图片制作，同时继续浏览或发起下一项制作。用户离开页面、刷新或暂时查不到进度时，仍需要知道任务是否已受理、执行到了哪一步，以及最后得到的是制作结果还是制作失败。切换演示身份时，用户应能验证当前身份的素材归属，并找回自己的制作任务记录。

## 解决方案

提供模板列表、模板详情和个人历史三个页面。用户在模板详情逐张上传素材，任务受理后留在当前页面，通过任务卡片跟踪制作阶段。制作任务由后台排队执行，页面关闭后仍可继续。个人历史按演示身份展示已经受理的任务，恢复尚未完成的跟踪，并提供制作结果或失败原因。

## 用户故事与验收条件

### 浏览模板和准备素材

1. **S01 · 按分类挑选模板。** 作为浏览者，我希望按分类筛选模板，从而找到想体验的制作样式。

   **验收**　列表显示标题和封面。选择某一分类时只显示该分类的模板，选择「全部」恢复完整列表。点击卡片进入对应详情。
2. **S02 · 理解模板要求。** 作为用户，我希望在选图前知道需要几张图、允许什么格式和大小，从而准备合适的图片。

   **验收**　详情显示标题、描述、封面和图片要求。单图与双图模板分别显示一个和两个上传位。
3. **S03 · 识别页面状态。** 作为用户，我希望分清加载中、空数据和加载失败，从而知道该等待、换分类还是重试。

   **验收**　列表和个人历史区分加载、空数据与请求失败，失败可重试。详情加载失败可重试，访问不存在的模板时可返回列表。
4. **S04 · 逐张上传和调整。** 作为用户，我希望预览、替换或移除每张选图，从而可以独立调整每个上传位。

   **验收**　选图即预览并上传。两个上传位中一个失败时，另一个保持就绪，失败位置可单独重试。替换或清空上传位后，先前上传的晚到响应不会填回该位置。
5. **S05 · 获得明确的校验反馈。** 作为用户，我希望尽早知道图片哪里不合要求，从而能修正输入。

   **验收**　格式、文件内容或大小不合要求时，显示可理解的反馈。绕过页面直接提交错误数量、无效素材或其他演示身份的素材时，服务端拒绝受理。必填上传位都就绪前，「开始制作」不可点击。

### 受理并跟踪制作任务

6. **S06 · 提交后立即看到制作任务。** 作为用户，我希望任务一经受理就看到独立的任务卡片，从而可以继续使用网站。

   **验收**　有效提交在制作完成前返回任务标识。受理后结束「提交中」，留在模板详情，在上传区下方展示新任务并提供个人历史入口。同一次提交请求进行中禁止重复点击。
7. **S07 · 复用素材连续制作。** 作为用户，我希望提交后能保留上传位里的素材，从而只替换部分图片就能发起下一项制作。

   **验收**　第一项任务受理后替换或清空上传位，第一项任务仍保有原有的有序任务输入。再次成功提交生成另一项任务，使用第二次提交时的素材，即使两次任务输入相同也有不同任务标识。
8. **S08 · 处理受理结果未知。** 作为用户，我希望提交超时后知道如何确认受理结果，从而避免无意中提交两次。

   **验收**　提交响应丢失或无法确认受理结果时，页面保留上传位，提供在新标签页查看个人历史的入口。页面不会自动重发制作请求。
9. **S09 · 连续提交并区分队列状态。** 作为用户，我希望第一项制作进行时仍能提交第二项，从而可以连续安排工作。

   **验收**　第一项任务尚在执行时，第二项任务可被受理并显示「等待处理」。第一项任务成功或失败后，第二项才开始。两张卡片的任务状态、制作阶段、失败原因和制作结果各自更新。
10. **S10 · 离开页面后继续制作。** 作为用户，我希望关闭页面后制作仍能继续，从而稍后回来查看。

    **验收**　任务受理后关页，重新打开个人历史能读到已推进的状态。成功任务依次经过素材检查、模拟生成和结果整理，每一步在服务端可观察。连续查询或停止查询都不会改变执行顺序。
11. **S11 · 查看制作结果或失败原因。** 作为用户，我希望知道制作最终得到了什么，从而能预览图片或理解失败。

    **验收**　成功时可预览对应模板的预置结果图，并标明模拟制作。任一阶段失败时，任务记录显示失败阶段和可理解的原因，后续步骤不执行。重复查询终态记录，仍得到原终态。
12. **S12 · 从进度查询异常恢复。** 作为用户，我希望暂时查不到进度时保留原记录，从而知道制作未被页面误判为失败。

    **验收**　单项任务查询超时后，其卡片保留上次的任务状态与制作阶段，并提示「暂时无法更新进度」。其他任务仍可更新。下一轮自动重试，用户也能点「立即重试」。查询恢复后清除提示。
13. **S13 · 刷新后继续跟踪。** 作为用户，我希望刷新页面后找回制作任务，从而可以继续查看进度。

    **验收**　个人历史从 Java 恢复记录，显示模板、创建时间、任务状态和制作阶段，按创建顺序倒序排列。刷新模板详情时恢复当前模板的未完成任务，上传位重新置空。恢复后的未完成任务继续更新，已达终态的任务停止自动查询。没有待跟踪任务或离开相关页面后，停止该页面的自动查询。

### 演示身份、异常与交付

14. **S14 · 切换演示身份并恢复个人历史。** 作为评审者，我希望分别以 A 和 B 体验制作，从而验证素材和任务按身份隔离。

    **验收**　选择 A 后可上传和提交。切到 B 后，A 的上传位、任务和个人历史不会显示，A 的晚到响应也不会写回。使用 B 的会话直接访问 A 的任务或使用 A 的素材，服务端拒绝。切回 A 可重新查看 A 的记录。
15. **S15 · 复现任一制作阶段的失败。** 作为评审者，我希望控制一项任务的制作耗时与失败阶段，从而能稳定验收排队与失败处理。

    **验收**　开启演示控制后，按 README 的命令可指定每项任务的阶段耗时，以及在素材检查、模拟生成或结果整理阶段失败。同批提交的正常任务仍可完成。关闭演示控制后，带模拟覆盖参数的请求被拒绝。
16. **S16 · 重启后看到明确的处理结果。** 作为评审者，我希望服务重启后能区分尚未开始和中途被打断的任务，从而知道任务现在处于什么状态。

    **验收**　重启前正在处理的任务记录为制作失败，保留阶段，原因注明「服务重启，处理已中断」。重启前等待的任务随后开始，已有终态记录保留。会话失效时，重选原演示身份可查看这些记录。
17. **S17 · 用键盘或小屏完成操作。** 作为用户，我希望在小屏和键盘操作下也能使用主要页面，从而可以完整走通制作流程。

    **验收**　列表、详情和个人历史的主要操作在小屏可达，详情区块按操作顺序纵向排列。交互控件有可理解的标签，键盘焦点可见，可完成筛选、选图、提交和查看结果。
18. **S18 · 在容器中启动并验证交付。** 作为评审者，我希望凭交付材料独立启动项目、运行检查和复现实例，从而可以核对规格。

    **验收**　`docker compose up --build` 启动前端、Java 和 MySQL，初始化模板数据。跟随 README 可完成正常制作、指定阶段失败、两项任务排队、刷新恢复和演示身份切换。CI 在 push 或 pull request 执行约定检查。

## 实现决策

### 系统边界与归属

- Next.js App Router、React、TypeScript 负责界面和状态跟踪。浏览器使用网站同源接口，Next.js 转发会话 Cookie、上传内容及响应。Java、Spring Boot、MyBatis 和 MySQL 承担题目规定的业务和持久化职责。
- 模板可公开浏览。上传和个人历史需先选择演示身份 A 或 B。Java 从 HttpOnly 会话 Cookie 识别归属，校验任务和素材权限。个人历史在服务端按当前演示身份过滤。会话和任务读取避免共享缓存。
- 素材文件存入本地数据卷，MySQL 保存模板、素材元数据、制作任务和有序任务输入。Java 校验真实文件大小和 JPEG 或 PNG 内容，再保存文件并返回素材标识。替换或清空上传位只修改当前表单。文件保留策略和整套演示数据重置方法由 README 说明。
- 自带至少两个模板分类、单图模板、双图模板、封面、预置结果图及可上传样例。默认每张图片不超过 5 MiB 和 2500 万像素，支持 JPEG 和 PNG。成功任务记录可加载的结果地址。公共预置图片不包含用户上传内容。

### 受理与执行

- Java 完成必要校验，在同一受理事务内保存等待处理的制作任务和有序任务输入。事务提交后返回任务标识。Java 单实例运行单个 worker，以 MySQL 为队列和任务记录来源，按任务序号领取已提交的等待任务。领取和状态更新带前置状态条件。
- 每一制作阶段开始前持久化当前阶段。步骤执行和模拟等待位于写事务之外。素材检查确认任务输入的文件仍可读。结果整理成功时一并保存成功状态及制作结果。失败时保存阶段和原因，终止本项制作并继续处理队列。
- 整体状态为 `PENDING`、`PROCESSING`、`SUCCEEDED`、`FAILED`。制作阶段为 `CHECK_ASSETS`、`GENERATE`、`FINALIZE`。等待时阶段为空。终态保留最后执行的制作阶段，查询接口只读取记录。
- 服务启动时，在 worker 领取任务前把遗留的处理中任务标记为 `PROCESS_INTERRUPTED` 导致的制作失败，保留原阶段。等待处理的任务仍可领取。
- Java 的演示配置开关允许提交时传入每项任务的模拟覆盖参数。默认每阶段 2 秒，`simulation.stageDelayMs` 可设为 0–10000 毫秒，`simulation.failAtStage` 可指定一个失败阶段。受理时固化模拟参数，README 提供命令演示。

### 页面与接口约定

- 模板详情显示当前访问中已加载的任务卡片，已达终态的卡片保留到离开页面。个人历史保留所有已受理的制作任务。页面分别管理上传、提交、任务状态和进度查询异常。
- 仅轮询等待处理和处理中的任务，默认每 2 秒一轮。同一任务的手动重试和轮询共享在途查询。离页或切换演示身份时清理定时器、取消请求并拒绝过期响应。身份切换结果不明时重新查询实际会话，再加载对应数据。
- 会话接口 `GET/POST /api/session` 查询或切换演示身份。模板接口 `GET /api/templates` 支持分类筛选，`GET /api/templates/{id}` 读取详情。模板响应包含封面、描述、分类及图片数量、格式、大小和像素约束。
- `POST /api/assets` 接收 `templateId` 和 `file`，上传成功返回 201 和素材标识。 `POST /api/tasks` 接收 `templateId`、有序的 `assetIds` 与可选 `simulation`，受理后返回 202 和初始任务记录。
- `GET /api/tasks` 查询个人历史，可按 `templateId` 和 `activeOnly=true` 过滤。 `GET /api/tasks/{id}` 查询单项任务。任务记录包含标识、模板、ISO 8601 创建时间、任务状态、制作阶段、可空的制作结果地址与可空的失败码和原因。 `GET /api/demo-images/{filename}` 提供内置图片。
- 无演示身份时，受保护接口返回 401。找不到模板、找不到任务或访问其他身份的任务时返回 404。参数或素材校验错误返回 400，上传超限返回 413。可控错误统一提供错误码和用户可读信息。
- Compose 为验收入口。MySQL 数据和上传文件使用持久卷。锁定经过验证的版本，提供数据库结构、种子数据、Dockerfile、无真实凭据的配置示例和完整前后端源码。

## 测试决策

自动化测试优先通过可被调用方观察到的行为断言结果。通过任务记录、公开接口、可见卡片和请求边界验证，不绑定私有方法或组件内部状态。项目从零开始，当前没有既有测试入口可复用。

| 测试入口 | 覆盖重点 |
| --- | --- |
| Java 制作工作流入口与任务查询 | 以可控阶段替身推进制作，分别观察三个阶段。对三个失败位置逐一验证失败原因、后续阶段未进入、终态稳定及下一项任务仍能执行。覆盖任务受理与有序输入写入、队列领取、只读查询和启动时的重启处理。对应 S06–S11、S15–S16。 |
| Java HTTP 接口 | 验证模板数据、上传校验、受理响应和演示身份隔离。用 B 的会话读取 A 的任务、引用 A 的素材，确认两种访问均被拒绝。对应 S01–S02、S05、S14。 |
| 前端页面交互与请求边界 | 注入两项制作任务，令其中一项查询失败，观察另一项仍能更新。推进时间验证异常恢复与终态停查，切换身份后交付晚到响应，验证旧任务无法覆盖当前页面。另测上传位替换、提交结果未知和刷新恢复。对应 S04、S07–S09、S12–S14。 |
| 容器手动验收 | 从空环境启动 Compose，按 README 操作，验证模板、上传、成功、可控失败、排队、关页、刷新、身份切换与重启。检查键盘和小屏。对应 S01–S18 的主路径。 |

TDD 从一条 Java 工作流测试起步。先验证正常任务的三个制作阶段按顺序可见，再加入指定阶段失败用例。接入持久化后验证受理、领取与终态记录。前端首条测试验证两项任务中一项遇到进度查询异常时，另一项仍能更新。

## 范围外

真实 AI 和媒体合成、支付、模板管理后台、生产账号体系、第三方登录、结果下载或删除、失败任务重新执行、执行中任务跨重启续跑、后端提交幂等、多实例 worker、公开部署和自动化浏览器端到端测试均不在本次范围内。
